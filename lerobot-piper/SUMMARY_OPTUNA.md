# Optuna 使用总结 —— 应对老师提问用

老师 2026-08-26 的技术指示是「**用 Optuna 取代手动肉眼调参**」。
本文汇总此后四次 Optuna 运行：设置、结果、以及**它在哪里停止起作用、为什么**。

---

## 1. 一句话

Optuna **成功了一次、判否了三次**，而且这四次合起来构成一个完整的论证：

> **参数层已经用尽。** 最后一次是把 3–9 Hz **明确写进目标函数**再跑的——
> 仍然动不了。所以剩下的缺口**不是调参问题**。

---

## 2. 四次运行一览

| # | 脚本 | 目标函数 | 自由参数 | 实际预算 | 最优值 | 结论 |
|---|---|---|---|---|---|---|
| ① | `optuna_ident.py` | IMU 带通残差/实测 | 24 | 1 seed × **2890** | 0.3956 | 修好了位形依赖；但目标含 IMU ⇒ 口径不纯 |
| ② | `optuna_ident_enc.py` | 关节位置 RMS / 行程（宽带） | **23** | 3 seed × ~1008 = **3026** | **0.030684** | **→ 冻结为 G-q-v1** |
| ③ | `optuna_ident_vel.py` | 关节**速度**带权 | 23 | 1 seed × **800** | 0.4795 | 判否（7 条门禁中 1/2/5 不过） |
| ④ | `optuna_ident_band.py` | 0.5·宽带 + 0.5·**3–9 Hz** | 23 | 3 seed × 1008 = **3024** | 0.2770 | 判否（5 条门禁中 3 条不过） |

合计约 **9700 次** trial。

## 3. 共同设置（四次一致）

| 项 | 值 | 为什么这么选 |
|---|---|---|
| 采样器 | `TPESampler(multivariate=True, group=True, n_startup_trials=40)` | **`multivariate=True` 联合建模参数耦合** —— 直接回应老师关心的「参数之间相互作用」 |
| 发散处理 | `PENALTY = 10.0`（有限大） | 用 `inf` 会毒化 TPE 的后验 |
| 存储 | `JournalStorage`（逐 trial 落盘） | 本机有偶发 SIGSEGV，崩溃不丢账 |
| 并行 | 16 个 spawn worker，**逐 worker 不同 sampler seed** | 见 §6 的踩坑 |
| 选参 | **只用训练损失**，留出集不参与 | 避免在留出集上调参 |
| 预算 | **事前定死，结束后不因结果接近而追加** | 预注册纪律 |

**自由参数是 23 不是 24**：`kp6 = 50` 是 `params.py` 里**预声明的 gauge**
（j6 的 `kp`/`c` 只有一个自由度，不固定就不可辨识）。①那次放开了全部 24 维，
是后来修正的口径问题之一。

## 4. 成功的那次（②）—— G-q-v1

**名称必须准确**：G-q-v1 = **「命令 → 编码器关节轨迹的有效预测模型」**。
**不得**称为「24 个真实物理参数已辨识的 G」。

相对此前**手工调参**的 G-π-phys-v1（各自调用自己的官方 `predict_*`、逐系列最优位移）：

| 集 | 关节轨迹 | IMU |
|---|---|---|
| 留出 A | −76% | −23% |
| 留出 B | −56% | −27% |
| pp2 | 0.7644° → 0.4304°（**−44%**） | 0.9797 → 0.5643（**−42%**） |

**一个独立旁证**：Optuna 辨识出的**有效跟踪增益**落在**厂商官方值**的
**0.21–2.47 倍**以内；而我们手工调软的 XML 偏离官方值 **2.3–13.4 倍**。
⇒ 自动搜索把参数拉回了物理上合理的范围，这不是靠拟合指标看出来的。

> **口径约束**：`kp` 一律称「**有效跟踪增益**」，不称真实机械刚度；
> `Ia`（armature）的个体值**不可解释**（只有 `(M_link+Ia)/kp` 可辨识）；
> `fc`（frictionloss）的值无意义。

## 5. 判否的三次 —— 尤其是 ④，这是最关键的一次

### 为什么需要 ④

②的损失是**宽带位置 RMS，没有任何带通**。而 3–9 Hz 只占关节位置能量的
**0.003%–0.12%**（pp2）/ 中位 **0.66%**（激励套件）
⇒ **那 23 个参数从来没有被"要求"拟合过这个带**。

在此之前的六轮改动（接触补丁 / 限幅器 / ΔH·u_hf / 学习式残差 / 速度目标 / planner）
全部失败，但一直留着一个可能性：**「也许只是目标没要求过它」**。
④ 就是为了排除这个可能性。

### ④ 的结果

把带内项**同权**写进目标（`L = 0.5·L_broad + 0.5·L_39`，两项**各自按自身尺度归一**）：

| | `L_broad` | `L_39` |
|---|---|---|
| G-q-v1 | 0.03068 | 0.5416 |
| 新 θ | **0.04507（+47%）** | **0.5090（−6%）** |

- 训练带内只改善 **6%**，代价是宽带恶化 **47%**；
- **留出 A 上的带内项反而变差**（0.5271 → 0.5620）⇒ 那 6% 没泛化；
- 诊断集 3–9 Hz 的 ρ² **0.204 → 0.202**（纹丝不动）。

**⇒ 参数层在 3–9 Hz 上确实到顶。这次是在「目标真的要求了它」的前提下测的。**

### 一个有意思的旁证

新 θ 确实把 **j3** 的 3–9 Hz 关节角 ρ² 从 0.647 提到 **0.825**——参数是能动关节的。
但陀螺没动，因为按**绝对**速度误差算，**j5 占 39.6%** 而新 θ 没碰它，
改的 j3 只占 18.7%，总误差只降 7%。
（j5 的 3–9 Hz 速度**基本等于没预测**：误差/信号 0.97，且**不是时序问题**——
最优位移只有 0.5 帧，对齐后 0.972→0.966。）

## 6. 过程中的踩坑（问到就说，主动讲更好）

**并行 worker 共用同一个 sampler seed。** 16 个 spawn worker 若共用一个 seed，
TPE 启动期（随机采样）会**逐字生成同一组参数**——并行预算全被复制品吃掉。
实际抓到过 trial 2 和 trial 3 的值完全相同（0.6970535830799548）。
修正为 `seed = SEED + 1009 × rank`。

**带内项权重形同虚设（本轮新踩）。** `0.5·MSE + 0.5·MSE(带通)` 里带通目标的方差
比宽带小约**三个数量级**，"0.5 权重"实际让带内项几乎不起作用。
必须**各自按自身尺度归一**。这个坑在 ④ 里做对了，但在后来的残差 FIR 里我又踩了一次
（折外 −3.4%，修正后 +3.6%）。

## 7. 老师可能问的

| 问题 | 回答 |
|---|---|
| **「Optuna 到底带来了什么？」** | 一次成功（G-q-v1，相对手工调参改善 23–76%），三次决定性的否定。后者同样有价值：它把「参数层还能不能救」这个问题**关掉了**。 |
| **「跑够了吗？会不会预算不足？」** | ④ 是 3 seed × 1008 trial，两个最好的 seed 收敛到 0.2770 / 0.2780（差 0.4%）。而且**每个 λ 都试过**：连最强正则那一档也只能把带内改善 6%。不是预算问题。 |
| **「为什么不放开更多参数？」** | 自由度不是瓶颈。①那次放开 24 维（含违反 gauge 的 kp6），23 维与 24 维的参数跨度中位分别是 289.4× 和 281.6×——**不可辨识性不是 gauge 造成的**。 |
| **「多目标 / Pareto 试过吗？」** | 试过（`pareto_screen.py` + `pareto_gate.py`，带约束的 Pareto 筛选、只用训练集选择）。 |
| **「为什么③只跑了一个 seed？」** | ③ 在第一个 seed（800 trial）就未过 7 条门禁中的 3 条，按预注册**不追加预算**。这是纪律，不是疏漏——但如实说明它只有单 seed。 |
| **「那接下来靠什么？」** | 不靠参数。转向「**物理底座（G-q-v1 冻结）+ 双层残差**」，3–9 Hz 从 0.193 提到 0.520。 |

## 8. 一句话收尾（建议这样说）

> 按您的指示改用 Optuna 之后，参数辨识确实有实质提升（相对手工调参 23–76%，
> 且有效跟踪增益回到了厂商值的量级）。之后我们又用它做了一次**决定性的否定实验**：
> 把 3–9 Hz 明确写进目标函数重跑，参数仍然动不了。
> 所以我们判断剩下的缺口不在参数层，转向了残差建模——这一步把 3–9 Hz 从 0.193 提到了 0.520。
