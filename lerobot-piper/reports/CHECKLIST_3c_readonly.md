# ③c 只读核验步骤（**不启用运动、不修改参数、不复放**）

草案 2026-09-21。**这份清单本身不构成放行依据**，它只是把
「安全审查需要的事实」从「跑实验」里分离出来。

## ⚠ 三条边界，执行前先读

1. **本清单全程只读。** 不发 `JointCtrl`、不使能电机、不改任何固件或 SDK 参数。
   一旦需要写参数或让臂运动，**属于另一个步骤，另行申请**。
2. **读到的限速/加速度不能直接与请求差分比较。**
   必须先确认它约束的是「**下发目标的变化**」还是「**控制器内部生成的运动轨迹**」。
   若是后者，请求的二阶差分超过它**可能只意味着控制器会整形** ——
   **既不直接证明危险，也不证明安全**。
3. **得到数字 ≠ 完成安全审查。** 本清单产出的是**事实**，
   是否放行由这些事实 + 适用性判断共同决定。

## R 阶段清单

### R1 环境与版本（不连臂也能做一半）

- [ ] `piper_sdk` 版本（`pip show piper_sdk` / `__version__`）
- [ ] 本机**固件版本**（SDK 的固件版本读取接口）
- [ ] CAN 接口状态（`ip -details link show can0`），**只看不改**
- [ ] `lerobot/common/robot_devices/motors/piper.py` 当前 git sha

### R2 控制模式与输入要求 —— **口径 2 的关键**

- [ ] 当前**控制模式**是什么（`MotionCtrl_2` 的 ctrl_mode / move_mode 实参含义）
- [ ] `MotionCtrl_2(0x01, 0x01, **100**, 0x00)` 的**第三参数**：
      - [ ] 是否为速度百分比？量程？
      - [ ] `100` 是上限还是默认？
      - [ ] 它作用于**下发目标的变化率**，还是**控制器内部插补轨迹**？
- [ ] `JointCtrl` 的输入语义：是**位置目标**还是**增量**？单位是否确为 0.001°？
- [ ] 该模式下固件**是否对连续位置目标做插补/限幅**？在哪一层？

### R3 限值读取 —— **必须同时记下单位与适用对象**

- [ ] 逐关节**限速**（值 + 单位 + 适用于目标变化还是内部轨迹）
- [ ] 逐关节**最大加速度**（同上）
- [ ] 逐关节**位置限位**（厂商侧的值，用于对照 `piper.py::write` docstring
      与 MuJoCo `jnt_range`）
- [ ] 上述值是**出厂默认**还是**本机已被改过**

### R4 与已冻结序列的对照（离线，读到值之后）

- [ ] 把 R3 的限值填进 `sim/audit_send_chain_3c.py` 的来源表，标注**适用对象**
- [ ] 重跑该脚本，看判读是否从第三支移出
- [ ] ⚠ 若限值约束的是**内部轨迹**而非下发目标，**不得**直接与请求差分比较 ——
      需另行确认输入要求

## 已知的、本清单不解决的

- `piper.py::write` 的 docstring 位置范围**与实机不符**：
  裸 `u` 的 j2 实到 106166（0.001°）而文档写 90000，且该轨迹已跑过 40+ 集。
  ⇒ **文档陈旧**是一种解释，但「跑过 40 集」是**经验依据**，
  **不足以单独证明文档错误或安全边界成立**。R3 的厂商侧位置限位可以澄清这一条。
- `piper.py::write` 发送路径**无软件速度/加速度限幅**（只做单位转换、取整、发送）。
  **不能假定 G 的限幅器在这里兜底** —— G-v2 的 `A_MAX` 是阶跃拟合的**模型参数**，
  且**裸 ACT 轨迹本身就超它最多 7.6×**。
