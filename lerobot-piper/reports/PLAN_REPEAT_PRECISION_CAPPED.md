## 0 只回答一个问题：重复精度

> 固定原名义轨迹、P / Q 波形和幅值，新的重复运行能否复现**正、负各自**的响应波形，以及它们的散布？

- **不比较模型**，不判定响应是否存在，不用于训练网络或放行 π。
- **不要求正负互为相反**：稳定的非线性响应同样可能有价值。正负分别评估；两者的关系只作辅助报告。
- 结果只决定一件事：是否值得**另行设计**正式响应数据采集。本方案不直接接续任何采集或训练。

## 1 固定项（与 pilot 相同，不改）

- **名义轨迹**：`ab5/A_ep0`（同一份 cmd7）。
- **探针**：P、Q 两条波形（同一组 `P_plus / P_minus / Q_plus / Q_minus` 计划序列），每条都有正、负两个符号。
  - 幅值同 pilot：标称 1.5 mrad RMS，在截取、门控及排除 j4 之前计；瞬时峰值上限 ε = 10 mrad；门控掩码同 pilot。
- **发送链**：发送计数 = round(rad × 57324.840764)，与计划计数逐帧一致才算有效（见第七节）。

## 2 记录与处理链（事前固定）

**记录**：每次复放完整保留以下数据，不在采集时做任何降采样或滤波：
- 100 Hz 原始 IMU 流 `imu100`：主机时刻、设备毫秒、加速度、陀螺；
- 指令时间戳：`t_send`（写总线时刻）及其不确定度 `t_send_span`；
- 读数时刻 `t`、发送指令 `cmd`、关节状态；
- 原来的 20 Hz「读数时最新样本」`imu`，用于和 pilot 衔接。

**主分析用 20 Hz**（先在 100 Hz 上抗混叠，再固定相位取样）；完整的 100 Hz 原始流全部保留，作辅助。

**主分析的处理顺序**（写死在 `sim/precision_chain.py`，不随数据调整；scipy 1.15.3 / numpy 1.26.0 下核对）：
1. **时间基准**：每次复放用 `np.polyfit(设备毫秒, 主机时刻, 1)` 做线性拟合，得到 100 Hz 样本的时刻（去掉接收抖动）；拟合残差的标准差记录在案。
2. **抗混叠低通**（在 100 Hz 上、取样之前）：
   - **系数**：`firwin(183, 9.0, window=("kaiser", 5.65326), fs=100)`。183 阶与 β = 5.65326 由 `kaiserord(60 dB, 过渡带 8–10 Hz)` 给出。
     系数按 float64 计算，sha256 前 16 位须等于 `f74b8d9914e4ee8d`，不符即拒绝（防止库版本改变设计）。
   - **零相位实现**：`filtfilt(b, [1.0], x, axis=0, padtype="odd", padlen=549)`，前后各滤一遍。
     等效幅频 |H|²：0–8 Hz 在 ±0.02 dB 内，9 Hz −12.0 dB，10 Hz 以上不高于 −120 dB。
   - **边界处理**：在整段 100 Hz 流上滤波；两端各做 549 点（= 3 × 183）奇对称延拓。
   - ⚠ 固定相位插值本身**不等于**抗混叠，所以这一步必须放在取样之前。
3. **固定相位取样**：在每帧「指令写入时刻 t_send − 5.0 ms」处取样，得到与指令时序锁定的 20 Hz 序列。
   - 插值：`CubicSpline(第 1 步时刻, 第 2 步结果, axis=0, bc_type="not-a-knot", extrapolate=False)`。
   - 不外推：任一取样点超出 100 Hz 流的覆盖范围，该次复放无效。
   - 偏移 −5.0 ms 取自 pilot 记录样本的中位位置，此后固定。
4. **计分带通**：沿用项目口径 `P(·)`，即去均值 → bandpass41（0.5–9 Hz）→ 丢首尾 20 帧。

**口径**：第 2 步会衰减 8–9 Hz，并去掉折叠进来的 10 Hz 以上成分。因此新处理链的数字与旧口径（pilot 的朴素 20 Hz「最新样本」，或收口诊断里未抗混叠的线性插值）**不能直接当同口径比较**；两者之差也不能归因于任何单一因素。

**辅助**（只报告）：
- 原来的 20 Hz「最新样本」序列按 pilot 口径再算一遍，用于和 pilot 的数字直接对表；
- 100 Hz 帧锁定序列（第 1–2 步后，在 t_send + {0, 10, 20, 30, 40} ms 取样）同样计算一遍。

**对 pilot 那个数字的准确说法**：在「固定相位线性插值重采样、未做抗混叠」的处理下，重复散布的标准差下降约 22%；这**不能全部归因于相位抖动**。本方案的处理链与那次不同，那个 22% 不作为本方案的预期值。

## 3 重复单位与指标（保留共享裸基线的不确定性）

**重复单位**：整次复放。正、负分别评估，四个条件是 P₊、P₋、Q₊、Q₋。

**为什么不能直接用 pilot 那种尖峰匹配当重复精度**：两遍都减去同一个裸基线时，基线误差是两遍共有的，会让两遍看起来更一致。所以主指标都按下面两种方式构造，避开这个共同误差：

1. **条件内散布 σ_c**（不涉及裸基线）：同一条件 n 次复放，以条件均值为中心的逐帧逐轴样本方差（÷(n−1)）的池化开方；复放级 df = n − 1。
   裸复放同样计算 σ_bare（df = M − 1）。四个条件合并的散布 σ_pool 只作汇总。
2. **分半复现度 R_c**（两半各用各的裸基线）：
   - 把复放按区组分成两半；每一半都有自己的同条件复放和自己的裸复放：r_c^甲 = 同条件均值^甲 − 裸均值^甲，r_c^乙 同理。两半之间不共享任何复放。
   - R_c = 1 − ‖r_c^甲 − r_c^乙‖² / (‖r_c^甲‖² + ‖r_c^乙‖²)。两半完全相同时为 1；两半不相关且功率相等时约为 0。
   - 若响应可重复、且噪声符合复放级独立模型，R_c 的期望约为 S² / (S² + Var_半)，S² 是响应功率。
3. **散布比 κ（只报告，不进判据）**：
   - 定义：两半之差的实测功率，与按 σ_c、σ_bare 预测的功率之比。Var(r^甲 − r^乙) 的预测 = σ_c²·(1/n_甲 + 1/n_乙) + σ_bare²·(1/M_甲 + 1/M_乙)。
   - **为什么不进判据（代数耦合）**：
     - 同一条件的 4 次复放有 3 种二对二的分法。三种分法的两半均值之差，平方后相加，恒等于这 4 次的总离差平方和 T。
     - 两种交错分法只用到其中两种，所以平均不超过 T/2。忽略裸基线噪声时，预测值是 σ_c²·(1/2 + 1/2) = T/3。
     - 因此 κ 按构造不超过 1.5。
   - 所以 κ ≈ 1 **不能**证明「整次复放独立」的噪声模型，也**不能**保证误差可按 1/√n 推算次数。
   - 四个条件逐个报告、合并的 κ_pool 也报告，都只作描述。

带通后帧间强相关，所有逐帧 RMS 类量的有效自由度都很少；上面的复放级 df 才是 σ 的自由度。

## 4 次数、顺序与预算（一套）

**组成：25 次**

| 项 | 次数 | 作用 |
|---|---|---|
| A0 独立对齐 | 1 | 当日对齐；不进任何指标，不得用探针结果反挑对齐 |
| 裸复放 | 8 | σ_bare、两半各 4 次的裸基线、漂移 |
| P₊、P₋、Q₊、Q₋ | 各 4（共 16） | σ_c（每个条件 df = 3，合并 df = 12）、两半各 2 次 |
| **合计** | **25** | |

**顺序**（4 个区组；每个条件每个区组出现一次，位置按拉丁方轮换）：

```text
1  A0
区组1：裸 P₊ Q₋ 裸 P₋ Q₊        区组2：裸 Q₊ P₋ 裸 Q₋ P₊
区组3：裸 P₋ Q₊ 裸 P₊ Q₋        区组4：裸 Q₋ P₊ 裸 Q₊ P₋
```

- **只是按序号平衡**：每个探针条件的四次平均序号相同（都是第 14 位），裸复放的平均序号是第 12.5 位。
  - 每次复放的实际耗时、复位和等待各不相同，所以这**不保证**各条件与各自裸基线在实际时间上平衡，也不声称漂移会相互抵消。
  - 保持现有顺序，不另作校正。报告按实际时间戳给出每个条件（及两种分半的每一半）与对应裸复放的平均时刻差。
  - pilot 在 16 分钟内没有分辨出漂移，这**不能外推**到本次最长 50 分钟。
- **分半**：主分析的 R_c 取区组 {1,3}｜{2,4} 和 {1,4}｜{2,3} 两种交错分法的平均。
  {1,2}｜{3,4}（前半对后半）只作漂移的辅助报告。

**预算（双上限，任一触顶即停；用户已接受，但接受预算不等于运动放行）**：

- **现场最多 50 分钟**：从开始计时算起，包含复位与等待。pilot 的实际节奏是 14 次 23.6 分钟，按此估 25 次约 40–45 分钟。
- **不预留补跑**：25 次尝试正好等于计划的 25 次复放。
  - 任何失败都照样记账并保留日志，按本方案记为「无法判定」。
  - 不临时追加次数；预算用完还没跑完，同样记为「无法判定」。

**预期精度**（冻结前的 pilot 离线复算；只核对预期精度，**不据此调阈值**）：
- 复算方法：pilot 已有的 100 Hz 原始流按第二节处理链重算（`sim/precision_chain.py`，产物 `outputs/pilot_response14_analysis/recompute_new_chain.json`，sha16 `dc3408c5b5e0f6a6`）。
- 复算结果（新口径）：
  - σ_adj = 0.0186（与 pilot 报告同一定义：6 对同条件复放，df = 6）；裸复放 σ_bare = 0.0203（df = 4）。
  - 四个条件的响应 RMS 为 0.058–0.065，去掉噪声项后的响应功率 S ≈ 0.059。
- 原来的 0.0353（朴素 20 Hz）和 0.0275（收口诊断的未抗混叠线性插值）改称**参考情景值**：两者口径不同，**不是**新处理链的上下界。

| 量 | 新处理链（σ = 0.0186，S ≈ 0.059） | 参考情景值 0.0353 / 0.0275（口径不同，S ≈ 0.065） |
|---|---|---|
| 全场次正负各自的 SE = σ·√(1/4 + 1/8) | 0.011 | 0.022 / 0.017 |
| 分半 SE = σ·√(1/2 + 1/4) | 0.016 | 0.031 / 0.024 |

- 裸项改用 σ_bare = 0.0203，期望仍约 0.93。
- 本方案的名义 95% 区间系数（与口径无关）：
  - 合并 σ_c（df = 12）：×[0.72, 1.65]；作对比，pilot 单个条件 df = 1，×[0.45, 31.9]。
  - σ_bare（df = 7）：×[0.66, 2.04]；作对比，pilot 的 df = 4，×[0.60, 2.87]。
  - 这些区间都以「整次复放独立」为前提，κ 不能验证这个前提（见第三节）。
- 响应不可重复时（S² = 0），R_c 约为 0。

## 5 判定规则（事前写死）

前提：**执行完整**，即 25 次都完成、都通过第七节的有效性核验，没有锁停或超时。否则直接记为「无法判定」。

只用 R_c（第三节第 2 项，取两种交错分法的平均），阈值 0.6 / 0.3 是工程阈值，不是显著性：

| 判定 | 条件 |
|---|---|
| **支持另行设计正式采集** | 四个条件的 R_c **都** ≥ 0.6 |
| **停止推进** | 四个条件 R_c 的平均 < 0.3 |
| **无法判定** | 其余情况；或执行不完整 |

- **「支持另行设计正式采集」（简称「支持继续」）的含义**：只表示本套分半设计下的复现度达到了工程阈值。
  - **不表示**总体测量精度已经验证，也**不表示**次数公式（按 1/√n 推算）已经验证。
  - 正式采集仍需另行设计、另行决定与授权。
- **停止推进**的含义：在本设计下，响应波形不能可靠复现。暂停响应建模分支，不扩采、不换网络。
- **无法判定**：不加次数、不补跑，记录现状，交用户决定。
- 规则只用主分析（第二节第 1–4 步）。κ 和其他辅助结果只报告，不改变判定。

## 6 辅助报告（不进规则）

- 正负两侧的关系：r₊ 与 −r₋ 的相关和功率比，只描述，不要求互为相反。
- 尖峰匹配：按第三节的分半方式计算，两半用各自的裸基线，作为 pilot 收口诊断的延续。
- 与 pilot 的跨日比较：pilot 的 100 Hz 原始流可以用同一条处理链复算，与本次的响应波形对比，只报告。
- **门控 / 量化边缘同位检查**：大偏差帧落在门控掩码边缘或发送计数台阶 ±1 帧内的比例，与这类帧的总体比例相比。只作辅助，不再另开一轮机制诊断。
- κ：四个条件逐个、以及合并的 κ_pool，按第三节的说明只作描述。
- 漂移：
  - 裸复放按实际时刻的三段比较与线性斜率；
  - 分半 {1,2}｜{3,4} 的差异；
  - 各条件（及每一半）与对应裸复放的实际平均时刻差（第四节）。
- 原 20 Hz 口径与 100 Hz 帧锁定序列下的同样指标（衔接用；与主分析不同口径，不直接比较）。

## 7 数据有效性与执行

**每次复放的有效性**（事前定好，任一不满足即视为失败）：
1. 记录文件的哈希与现场账本一致；
2. 发送计数与计划计数逐帧一致；
3. 100 Hz 设备时间戳在复放期间连续，没有超过 15 ms 的间隔；
4. 原 20 Hz 样本都能在 100 Hz 流中找到完全相同的值（记录完整性核验；pilot 14 次都是 100%）；
5. 写总线的间隔没有超过 100 ms（pilot 最长 65 ms）。

**执行**：
- 另写专用入口，不修改 pilot 的文件；沿用 pilot 的安全模型：
  - 冻结文件与授权核对、现场账本、双上限；
  - 失败即锁停，不自动重试，无通用 `--force`；
  - 每条复放由现场人员 `--operator-ready` 显式执行；
  - 脚本退出不代表禁能。
- 任何一次失败都照样记账、保留日志；不预留补跑，判定按第五节记为「无法判定」。
- 旧③c 的默认硬阻断保持。运动需要用户另行明确授权；**本方案和对预算的接受都不构成运动放行**。
- 采集时不同时运行训练、复跑或压力测试；主机内存检测另外安排，不作为前置条件。
