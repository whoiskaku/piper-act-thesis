# 实施计划 —— 重复精度封顶验证（25 次）的专用脚本

**状态：草稿（2026-10-05），待用户审阅。零机时：不连接机械臂、不启动采集、不训练网络或 π。不授权运动。**
- 依据：冻结的实验设计 `reports/PLAN_REPEAT_PRECISION_CAPPED.md`（76785f5）。本计划只实现它，不新增实验问题、条件或判据。
- 范围仅限：采集入口、单次复放执行器、分析脚本、测试。pilot 的文件不改；pilot 产物只读。

## 1 文件

| 文件 | 作用 |
|---|---|
| `sim/run_repeat_precision25.py` | 采集入口：冻结输入、账本、双上限、失败锁停、逐条完整性核验、A0 对齐 |
| `sim/replay_repeat_precision25.py` | 单次复放执行器（第 3 节） |
| `sim/analyze_repeat_precision25.py` | 分析与判定 |
| `sim/test_*_repeat_precision25.py` | 入口、执行器、分析、端到端四组测试（第 5 节） |
| `outputs/repeat_precision25/` | 从 pilot 复制并按 pilot manifest 哈希核对的冻结输入（A / P± / Q± 序列、发送计数、标定参考）、manifest、账本、记录 |
| `reports/RELEASE_REPEAT_PRECISION_25.json` | 冻结时写入代码指纹，`motion_authorized: false`（第 6 节） |

## 2 采集入口

- **命令**：与 pilot 相同的五个，`--prepare`（离线复制并锁定输入、写 manifest）、`--dry-run`、`--status`、`--start-session --operator-ready`、`--run-next --operator-ready`。
  没有 `--force`，没有重试、跳过或补跑。一次调用只执行固定顺序里的下一条。
- **顺序**：写死为方案第 4 节的 A0 + 4 个区组，共 25 条；每条的条件和符号取自 manifest，不从名字推断。
- **预算封顶**：
  - 每次尝试在连接设备**之前**记账，初始化失败也消耗一次；第 26 次一律拒绝。
  - `--start-session` 开始 50 分钟现场时钟，复位与等待都计入。剩余不足 60 秒时拒绝开始下一条。复放进行中到「截止前 15 秒」即停止采集、分段归位，记为失败。
  - 重启机器、删除或重建账本都不能重置预算。
- **失败锁停**：出现以下任一情况，账本标记 `halted`，此后所有 `--run-next` 都拒绝执行，按方案记为「无法判定」：
  - 退出码非 0、出现异常、归位受阻；
  - 预移动或稳定门禁不过；
  - 完整性核验不过。
- **记录完整性**（每条结束立即核验，不过即失败锁停；分析时再独立复核一遍）：
  1. 记录哈希写入账本；
  2. 发送指令与冻结波形逐帧完全一致，且换算出的发送计数与计划计数一致；
  3. 100 Hz 设备时间戳单调，最大间隔 ≤ 15 ms；
  4. 每个 20 Hz 样本都能在 100 Hz 流中找到相同的值；
  5. 写总线间隔 ≤ 100 ms；
  6. 另查：身份字段、帧数与有限值；处理链的取样点必须全部落在 100 Hz 覆盖范围内（不外推）。
- **A0**：只用 A0 和冻结的标定参考确定对齐（与 pilot 同法）；对齐冻结之前拒绝任何探针条。A0 不进任何指标。

## 3 执行器（请你确认）

- **问题**：`replay_probe.py` 的放行钩子写死为 `run_pilot_response14`，只认 pilot 的 release。不改 pilot 文件，它就不能为本次放行。
- **推荐做法**：另写执行器，照搬 pilot 已实测 14 次的执行路径，只把授权核验换成本次入口。
  - 照搬的路径包括：预移动、位置带与到位门禁、采集循环、分段归位，以及「清理时不额外发归位或禁能」。
  - 纯函数（`safety_checks`、`staged_return` 等）从 `replay_probe` 导入，并锁定其哈希。当前哈希与 pilot release 记录的一致。
  - pilot 执行器的离线回归（作用域核验 10 项、故障路径 11 项）移植到新执行器。
- **不推荐**：
  - 改 `replay_probe.py` 的钩子：这等于修改 pilot 文件；
  - 运行时替换模块：虽然复用了原字节，但把授权绑定藏了起来。
- **与 pilot 执行路径唯一的行为差异（请你确认）**：打开 100 Hz 记录后，先以 20 Hz 继续发送稳定段的同一保持指令 0.2 秒（首帧位姿，臂不动），再开始第一帧。
  - 原因：在 pilot 的 14 条记录里，100 Hz 流起点早于首帧取样点（t_send − 5 ms）的余量最小只有 3.2 ms，中位约 20 ms。
  - 按冻结处理链的「不外推」规则，余量一旦为负，该条就无效，整轮记为无法判定。
  - 记录队列无上限，0.2 秒不会溢出。处理链和判据都不变。

## 4 分析脚本

- **先核验**：25 条全部完成；记录哈希与账本一致；逐条有效性复核；代码指纹与 release 一致。
  任一不满足 ⇒ 「无法判定」，只报告执行现状，不计算主指标。
- **主分析**：`precision_chain.frame_locked` → `P(·)`；A0 不参与。
  - 散布：σ_c（每个条件 df 3，合并 df 12），σ_bare（df 7）。
  - 复现度：R_c 取 {1,3}｜{2,4} 和 {1,4}｜{2,3} 两种分法的平均。
- **分半基线不共享**：两半直接由区组表构造。断言两半复放集合不相交，每半恰好是 2 次同条件加 4 次裸复放，且裸复放只来自本半的区组。
- **判定**：纯函数，只接收「执行是否完整」和四个 R_c，三种出口：
  - 四个都 ≥ 0.6 → 支持另行设计正式采集；
  - 平均 < 0.3 → 停止推进；
  - 其余情况 → 无法判定（任一 R_c 非有限也记为无法判定）。
- **辅助报告**（方案第 6 节）：单独一节输出，在判定之后计算，不能流入判定。内容包括：
  - κ、正负关系；
  - 分半尖峰匹配、门控 / 量化边缘同位；
  - 按实际时间戳的漂移与时刻差；
  - 旧 20 Hz 口径、100 Hz 帧锁定、与 pilot 的跨日对比。
- **产物**：`outputs/repeat_precision25_analysis/analysis.json`，记录其哈希。

## 5 测试（全部离线；任何测试都不得到达真实设备工厂；产物只写临时目录）

- **入口**：
  - 移植 pilot 入口的 21 项，改为 25 条；
  - 新增：每类完整性失败都会锁停、第 26 次拒绝、截止时刻的两道闸、CLI 没有 `--force`。
- **执行器**：上述 21 项移植；新增 0.2 秒预滚动保证覆盖的测试。
- **分析**：
  - 分半不共享：集合断言，以及只扰动区组 2、4 的裸复放时，{1,3} 半的响应不变；
  - 判定边界：恰为 0.6、恰为 0.3、非有限、不完整；
  - 篡改哈希或任一有效性失败 ⇒ 无法判定。
- **端到端**：
  - 假设备：100 Hz 陀螺带设备毫秒、主机抖动和逐次相位；20 Hz 取最新样本；提供写总线时刻；响应由各条件的 δa 决定。配合假时钟，经入口 → 执行器 → 记录 → 分析跑满 25 条。
  - 场景：
    - 可复现响应 → 支持；
    - 无响应 → 停止；
    - P 有、Q 无 → 无法判定；
    - 第 k 条注入故障 → 锁停 → 无法判定；
    - 时钟触顶 → 拒绝下一条。
  - 每个场景跑两遍，分析产物哈希一致（主机硬件不稳定的防护）。
