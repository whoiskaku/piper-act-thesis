## 2. 最重要的发现：跟踪误差的位姿依赖，且无法外推

| 来源 | j3 跟踪 p99 |
|---|---|
| 预算（无往复的任务数据） | 0.122° |
| P1 · 289（dither 1.0°） | 0.3011° |
| P2 · 56（dither 1.0°） | **0.4393°** |
| P3 · 753（dither **2.0°**） | **0.2726°**（最小） |

- 预算低估 2.2–3.6 倍。
- **与 dither 幅值无单调关系**：幅值翻倍的 P3 反而最小。
- 用 P1 外推 P2 得余量 0.215°，实际同位姿门只有 **0.0225°（小 10 倍）**。

⇒ **完整采集必须逐位姿 `A → 同位姿门 → B± → A`**，不能用预算表或任何外推。
这会增加机时，但从 P2 的 0.0225° 看省不得。

## 3. 同位姿门的保守性（已量化，但不是紧预测器）

门把 `|编码器−命令|` 的 p99 整个当作朝边界的偏置。实测三位姿的
"编码器最近 − 命令最近" 为 **−55.2 / +25.2 / −51.0 mdeg**——三个里两个为负
（编码器反而更远），符号与量级都不稳。

绝对值均 <60 mdeg 而 p99 是 270–440 mdeg ⇒ **高估的核心论点成立**，
但它**不能当预测器**（P2 那次 10 mdeg 的吻合是偶然）。

物理原因：跟踪误差峰值在摆动中段（速度最大），最接近边界在摆动极值（速度≈0）。

P2 实测编码器最近 0.752°，在 0.3° 预留之外仍有 0.45°。

## 4. 三处必须记录的修正（都是分析侧的错，不是采集或硬件）

1. **偶分量判据**：初版用 `|even|/|noise| < 2` 判"相容"是拍的。
   单窗口下 even 与 noise 各只有一个复样本 ⇒ `|even|²/|noise|² ~ F(2,2)`，
   95% 分位比值 = **4.36**，"比值>3"在零假设下就有 10% 频点出现。
   改用正确阈值后：**三个位姿全部与噪声相容**（超阈 0/13、1/13、1/4，
   零假设期望 0.65/0.65/0.20）。我曾据旧判据报 P3"显著高于噪声"，**作废**。
2. **C3 标签**：`planned_travel = −adir` 只看进场偏置符号、**忽略 dither 斜坡**。
   P1/P2（dither 1.0° < 偏置 1.5°）正确；P3（dither 2.0° > 1.5°）net 行程被
   dither 淹没到 −0.093°，标签遂与实测不符。命令与编码器符号一致
   （−0.093° vs −0.036°）⇒ **不是硬件问题**。
3. **设计层面的后果**（比标签重要）：P3 的 j3 进场净行程只有 0.09°，
   **"统一进场"对该关节实际上没有发生**。不过该关节全程连续 dither，
   背隙状态由 **C2 相位**而非进场方向决定，而 P3 的 C2 spread 是三者最好的
   **0.50°** ⇒ 一致性仍然成立，只是由另一个机制保证。
   完整采集若要 C3 对所有位姿都有意义，进场偏置须 > 该位姿的 dither 幅值。
