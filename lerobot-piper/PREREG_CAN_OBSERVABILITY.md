## 0. 为什么做这一步

`RESULT_OPTUNA_IDENT_ENC.md` §28 的结论：G-q-v1 在 pp2 上
**0.5–3 Hz 形状好（ρ²=0.710，最优增益 1.06）/ 3–9 Hz 形状差（ρ²=0.107）**，
而把**实测编码器**喂进同一套刚体传感器映射，3–9 Hz 也只到 ρ²=0.487。
六轮（接触补丁 / 限幅器 / ΔH·u_hf / 学习式 HF 残差 / 速度目标 / planner）全部失败，
因为它们都不在**关节→IMU 这一层**上。

在放弃 3–9 Hz 之前还剩一个低成本中间步骤：**Piper 的高速电机反馈一直在 CAN 总线上，
只是从来没有落盘。** 当前 `PiperMotorsBus.read()` 只存 6 个关节角 + 夹爪。

**本试验不改 G、不改动作、不加硬件。**

## 1. 已核实的接口事实（2026-09-01，装机 SDK 实读）

| 事实 | 出处 |
|---|---|
| `GetArmHighSpdInfoMsgs()` = `GetMotorStates()`，返回 `time_stamp`/`Hz`/`motor_1..6` | SDK docstring |
| 每电机字段：`can_id`、`motor_speed`(0.001 rad/s)、`current`(0.001 A)、`pos`、`effort`(0.001 N·m) | 同上 |
| **六个电机是六条独立 CAN 帧**(0x251–0x256)，写进**同一个结构体**，`time_stamp` 被最后到达者覆盖 | `piper_interface_v2.py:1836+` |
| 帧时间戳 = `rx.timestamp` = 内核 `SO_TIMESTAMPNS` = **CLOCK_REALTIME** | `piper_protocol_v2.py:69` → `socketcan.py:649` |
| 管线时钟 = **CLOCK_MONOTONIC**（`t`/`t_send`/TSND `host_t`） | `replay_probe.py:497` |
| `cal_effort()` J1–J3 ×1.18125、J4–J6 ×0.95844，**与固件版本无关** | `arm_feedback_high_spd.py:76,92` |

**由此定下两条口径**：

- **不轮询 `GetArmHighSpdInfoMsgs()`。** 在 20 Hz 控制环里轮询它 = 对六路异步流做
  无抗混叠抽取，**与我们在 TSND 上踩的坑完全同型**（`step2_ceiling.py`）。
  改为**被动监听 CAN**（独立 socket、只读、不发帧、不与控制回路争用）。
- **effort 只作激励代理，不称真实关节力矩。** 落盘保留原始 `current`。
  旧固件（1.8-2 及以前）J1–J3 另有倍率规则，而 SDK 系数不随固件变。

## 2. 步骤

### 第 1 步：静止 10 秒（无门禁，纯测量）

`sim/step3_canobs/probe_highspd_rate.py`。**不使能机械臂。** 报告：
逐关节实际 Hz、帧间隔中位/p99/最大、疑似缺样、静止时 speed/current 的 σ（量化底）、
六路之间的帧错位、REALTIME↔MONOTONIC 偏移及 10 秒内漂移。

**放行条件**（不满足则本条线终止，不进第 3 步）：
单关节实际 Hz ≥ 20 🔧，即 Nyquist ≥ 10 Hz，才谈得上覆盖 3–9 Hz 评价带。

### 第 2 步：扩展记录器（已实现）

`sim/step3_canobs/can_hs_recorder.py` + 接入 `replay_probe.py`（默认开，`--no-canhs` 关）。
同步落盘：100 Hz 原始 TSND(`imu100`) · 实际 `t_send`/`t` · 六关节高速
`pos/speed/current`(原始整数) · 固件/SDK/协议版本 · 两个时钟的偏移(`can_hs_meta`)。

`wait_first()` 是必须的：SocketCAN 允许 bind 到 state DOWN 的接口，
`start_recording()` 照样返回 True，然后**静默录到零帧**。

### 第 3 步：4 条 pp2 诊断集，分两个会话

序列用现成的 `outputs/probe/probe_seq_pp2_ep{0,1}.npz`。
每会话跑 ep0 + ep1，共 2 会话 4 条。同一会话内的两条给"会话内"基线，
跨会话给"跨会话"稳定性——这正是门禁要问的。

### 第 4 步：统一抗混叠口径

所有 20 Hz 比较，真机与仿真用**同型**滤波：真机侧从 100 Hz `imu100` 经
`butter(4, 0.45*20/(100/2))` 低通后 5× 间引，与 `g_q_v1.py:231` 仿真侧
（1 kHz → 9 Hz 低通 → 20 Hz）同型。

> ⚠ **口径断点**：现有 17 集 pp2 开发基准集**没有 `imu100`**，无法补抗混叠。
> 因此这 4 条新诊断集的数字**不能与 17 集的历史数字直接并列**，
> 引用时必须分开写。§28 表里的 ρ²=0.107 / 0.487 属于旧（混叠）口径。

## 3. 事前停止门（只回答一个问题）

> **高速电机速度/电流是否与腕部 3–9 Hz 残差稳定相干？**

残差定义 = 实机 IMU − G-q-v1 预测 IMU，带通 3–9 Hz，统一抗混叠口径。

**公平性约束（必须遵守）**：两个基线用**同一类预测器、同一留出、同一滤波**。
不能拿"拟合过的电机模型"去比"没拟合过的运动学映射"——
那正是我 2026-08 犯过的评估壳错配（`feedback_eval_harness_mismatch`）。
即：从 20 Hz 编码器和从高速电机状态，各拟合一个同阶线性预测器。

| 判据 | 阈值 |
|---|---|
| 多元相干 γ²_multi（六路电机 → 三轴残差，3–9 Hz 带内均值） | 两个会话**各自独立**算出来都 ≥ 0.35 🔧 |
| 两会话 γ²(f) 曲线的相关 | ≥ 0.5 🔧（形状一致，排除各自拟合噪声） |
| 3–9 Hz 的 ρ²（**整会话留出**） | 电机版 − 编码器版 ≥ +0.10 绝对 🔧 |

- **三条全过** → 继续，进第 4 节。
- **任一不过** → **立即停止 3–9 Hz**，正式把 G 的可信带限定为 0.5–3 Hz。

## 4. 通过后的下一步（不上神经网络）

复用标准 **MIMO 子空间辨识 / N4SID**：输入六路电机激励，输出三轴 IMU 残差，
模型阶数**固定扫 2–12**，**整会话留出**。不做阶数之外的搜索，不追加预算。

### 并入 G 的条件（**全部**满足才并入）

1. pp2 总体至少改善 **10%**；
2. 3–9 Hz 形状明显改善（ρ² 提升 ≥ **0.10** 绝对 🔧）；
3. 多数集改善（≥ **2/3** 集 🔧）且逐集中位为正；
4. 低频与关节轨迹不退化（0.5–3 Hz ρ² 下降 ≤ **0.02** 🔧，关节轨迹 RMS 上升 ≤ **5%** 🔧）；
5. **识别出的模态能由 MuJoCo 预测的 effort 驱动**，而不是依赖真机反馈才能工作。

> 第 5 条是硬约束，不可用真机反馈变通：G 是给 π 当训练环境的，
> 推理时**没有真机**。真机反馈只能出现在辨识阶段。

## 5. 失败后的路径

若本试验失败，把 π 的损失限制到 0.5–3 Hz。**但即使那时**，
也必须先在 0.5–3 Hz 重新跑一次 **π 的增量通道门禁**——
绝对通道的 ρ²=0.710 **不能自动授权 π**（增量通道跨关节 4.9× 的判停仍然有效，
见 `BPRIME_GQ_INCREMENTAL_GATE.md`）。
